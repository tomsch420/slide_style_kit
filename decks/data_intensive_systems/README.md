# Data-Intensive Systems

The *Advanced Methods of AI* lecture of 26.11.2026, between *Optimization* and
*Uncertainty*: why databases are a vital component of modern AI systems, and the design
decisions behind them. It follows M. Kleppmann's *Designing Data-Intensive
Applications* and reuses the course's kitchen robot: the Semantic Digital Twin, NEEMs
and EQL (lecture 02), triple stores (03), the closed world (04), Datalog (05) and SGD
(06). Built with `slide_style_kit` from the deck of the winter term 2024/2025.

| File | Content |
|---|---|
| `data_intensive_systems.py` | The deck; renders the charts, then writes `.pptx` and `.pdf` next to it |
| `examples.py` | What the slides compute: a pose database in SQLite, the same poses stored with ORMatic and queried with EQL, simulated response times (numpy, matplotlib), a kitchen graph queried with SPARQL (rdflib) |
| `poses.py` | The pose dataclasses: the domain model both pose databases store |
| `generate_pose_interface.py` | Generates `orm/pose_interface.py` with ORMatic; rerun it when `poses.py` changes |
| `orm/pose_interface.py` | The generated SQLAlchemy interface of the poses (tracked, excluded from `krrood check`) |
| `snippets/` | Code and data shown on the slides or run by `examples.py`; `put_away.prolog` and `put_away.sql` give the same answer |
| `charts/` | Rendered charts (not tracked; regenerated by every build) |
| `figures/` | Images cropped from the 2024/2025 deck (not tracked, see below) |

## Build

From the repository root, in its `.venv`:

```bash
cd decks/data_intensive_systems
python data_intensive_systems.py
```

The figures (the book's illustrations, the *Clean Architecture* charts, the DB-Engines
ranking, the PyCRAM database screenshots) come from the original PDF and are ignored by
git like every deck's `figures/`; the build needs them in `figures/`.
